# GestureWall

macOS 手势音乐壁纸。三张你自己准备的图（背景 / 主体 / 碎片）按景深排成一个有立体感的动态壁纸，手势控制它，跟随正在播放的音乐变氛围。

## 跑起来

```bash
cd wallpaper
npm install   # 会自动取 vendor（约 24MB，优先从本机 AirCursor 拷）
npm start
```

启动后出现**启动页**（点一下进入）和**壁纸**。进去是 Dashboard，左侧四栏：

| 栏 | 干什么 |
|---|---|
| **模板** | 三层图片、组合方式（每层三种表现）、景深排布、预设 |
| **图库** | 攒素材，指派到三层 |
| **手势录制** | 开摄像头、录手势、调手感 |
| **壁纸与音乐** | 窗口层级、音乐联动、诊断开关 |

| 快捷键 | 作用 |
|---|---|
| `⌃⇧W` | 打开设置 |
| `⌃⇧L` | **换壁纸层策略**（看不见壁纸时按这个） |
| `⌃⇧R` | 复位视角 |
| `⌃⇧Q` | 退出 |

⚠️ 壁纸层不一定收得到鼠标，所以退出只能靠 `⌃⇧Q`。

## 第一次用

1. 「模板」栏或「图库」里选三张图：
   - **背景** —— 整张壁纸，任意格式
   - **主体** —— 抠好的人物，**透明 PNG**
   - **碎片** —— 壁纸里的一小块（脸部之类），透明 PNG 最好
2. **看不见壁纸就按 `⌃⇧L`** 循环三种策略：

| 策略 | 是真壁纸吗 | 收鼠标吗 |
|---|---|---|
| `desktop` | ✅ 真壁纸层 | ❌ 官方文档说 desktop 类型收不到键鼠 |
| `普通窗口压到最底` | 半 —— 会出现在 Mission Control | ✅ |
| `悬浮最上层` | ❌ 不是壁纸 | ✅ |

**三种都留着是因为哪种在 macOS 上真能用没法从文档推出来。** `type:'desktop'` 映射到 `kCGDesktopWindowLevel - 1`，也就是**桌面背景之下** —— 如果系统壁纸不透明它可能压根看不见。所以三种都实现了，运行时切换，而不是在写代码时赌一个。

**先用「悬浮最上层」验视觉效果**，再换 `desktop` 试真壁纸。

3. 鼠标操作（在能收鼠标的策略下）：
   - 移动 = 视差跟随
   - 拖动 = 转主体
   - 滚轮 = 推近拉远

4. 手势（设置里开）：
   - **双手**拇指+食指捏合，两手**拉开 = 推进放大**，**合拢 = 拉远缩小**
   - **单手**移动 = 视差跟随
   - **快速横挥** = 主体左右转
   - **手掌上下倾斜** = 视角上看/下看（棘轮：抬一次动一格，手回中位才能再抬）

   手感不顺就动设置里那六个滑块。用的是 AirCursor 的 `PointerFilter` /
   `SwipeDetector` / `TiltRatchet`，所以那边的调参经验通用。

5. 音乐（可选）：
   ```bash
   brew install media-control
   ```
   读的是 macOS 的「正在播放」，所以网易云、Apple Music、浏览器都算。**没装就只是不跟音乐，壁纸照常。**

## 设计上的几个决定

**鼠标先接，手势后接，两者写同一份视角状态。** 这样「排布好不好看」能用确定的输入先验完，再谈「手势准不准」。两个一起 debug 的话，同一个症状会有四五种可能原因。

**zoom 是相机推进，不是把层放大。** 推镜头会同时改变层间视差，那才是"进去了"的感觉；缩放层只是把图放大。

**音乐氛围从封面推，不从音频。** 歌在网易云自己的客户端里播，我们拿不到音频流 —— 没有频谱、没有 BPM。封面是系统唯一交出来的丰富信号。输出连续值而不是"激情/舒缓"标签：标签错了很显眼，连续值错了只是氛围偏一点。

**碎片位置是 index 的函数，不用 `Math.random()`。** 随机的话每次重启壁纸都重新洗牌，永远调不出一个满意的排布。

**摄像头单独一个隐藏窗口。** 壁纸层可能不可聚焦，而在不可聚焦的窗口里 `getUserMedia` 会弹一个没人能点的权限框。分开也意味着手势挂了壁纸照样画。

## 测试

```bash
npm test      # 205 项纯逻辑用例，不需要 Electron / GPU / 摄像头
npm run check # 语法
```

失败时 exit 非 0 —— 是守卫不是日志。

⚠️ **它们证的是几何、数值和判定逻辑，证不了"画出来好不好看"和"真手能不能认出来"。** 用的是合成夹具（规则形状的假手、纯色像素），真手的抖动/丢帧/时间相关噪声都不在里面。那些只能真机看。

写这批用例的过程中逮到五个真 bug：碎片共享纹理却各自 `dispose()`（会崩）、换歌后旧封面永不释放（判断写在赋值之后所以恒为 false）、`WallScene` 直接读 `window` 导致整层无法测试、**归一化坐标喂给按像素标定的模块导致挥动永久失效**（掌宽被钳到 60，速度全变 0）、**预设字典被深合并吃掉**（用户存的排布下次启动全丢且不报错）。

```
src/

  preload.js     三个窗口共用的桥
  nowplaying.js  读「正在播放」（TrackTracker 是可测的那部分）
  layers.js      场景与控制律 —— 无 DOM，可跑用例
  mood.js        封面 → 氛围 —— 纯数学，可跑用例
  input.js       关键点 → 手势事件。判定委托给 AirCursor 的
                 pose/motion/tracking（vendor 里，只读不改）
  wall.html/js   壁纸窗口
  settings.html/js  设置窗口
  sensor.html/js    摄像头窗口（隐藏）

```

`layers.js` / `mood.js` / `gestures.js` 刻意不依赖 DOM、Electron、MediaPipe —— 所以能在没有图形环境的地方跑用例。

## 还没做

- 立体感目前是**三层视差 + 平面倾斜**，不是真 3D 主体
- 手势动作钉死，没有录制/自定义（AirCursor 有录制，还没接过来）
- 没有音乐控制（暂停/切歌）—— 只读不写
- 单显示器
- 没打包（`npm start` 跑源码）

## 手势判定为什么不是自己写的

`input.js` 把判定全部委托给 AirCursor 的 `pose.js` / `motion.js` / `tracking.js`
（由 `fetch-vendor.sh` 拷进 `src/vendor/aircursor/`，**这边只读不改，要改改源头**）。

第一版是自己写的 145 行最小实现，用户试完的反馈是"有反馈但效果不好"。作废它的理由
不是代码重复，是缺的三样正好一一对应那句反馈：

| AirCursor 有 | 我原来的 | 症状 |
|---|---|---|
| `OneEuroFilter`（截止频率随手速自适应） | 固定 `rate=5` 指数平滑 | 慢速够顺但快速迟钝，调快则静止时抖 —— 两头不讨好 |
| `SwipeDetector`（净位移 + 直线度 + 要求手腕先停下才重新武装） | 只判速度和方向 | 误触，且**回手被当成第二次挥动** |
| `TiltRatchet`（抬一次动一格，回中位才能再抬） | 无 | 没有可重复的离散输入 |

整合时踩到一个只有跨项目才会出现的坑：**AirCursor 全程假设像素坐标**，而这个假设烧进
了常数里（`palmWidthOf` 有 `Math.max(60, ...)`、`PointerFilter` 的死区是 1.6px）。
MediaPipe 给的是归一化 0..1，直接喂进去不是"精度差一点"而是**彻底失效** —— 掌宽被钳到
60，所有按掌宽归一的速度都除以 60 变成 0，挥动永远触发不了。所以 `input.js` 进出都做
一次单位换算（`FILTER_SPACE = 1000`）。

## 模板和手势是绑定的

一个模板 = 三个槽位的模块选择 + 一套它认的手势（分 basic / pro 两档）。

```
景深舞台
├─ 槽位   背景[静止/缓慢推移/随音乐呼吸]
│         主体[静止/呼吸浮动/跟随视角倾斜]
│         碎片[环绕/单侧聚集/前后穿插]
├─ basic  推进拉远 · 视差跟随
└─ pro    左转 · 右转 · 上看 · 下看 · 360旋转 · 复位
```

**手势不是一份全局列表**，而是模板的属性 —— 换模板就换一套可用动作。加第二套模板
只需在 `templates.js` 加一条，不用碰渲染和录制代码。

`continuous` 类动作（推进拉远、视差）由手的连续状态直接驱动，**不可录制** ——
录一个静态姿势对它们没有意义，而给它们做录制入口只会让人以为录了才能用。

## 手势录制

从 AirCursor 搬过来的状态机（`recorder.js`），抽掉了 IPC 耦合。搬而不是重写，因为里面
有一串只有真机才能发现的教训，每条现在都是一个用例：

- **手多了是 tracker 抖动，不是用户错**。录单手手势时 MediaPipe 在某些角度会间歇报出
  第二只手，把那当成"手数不对"会让每次闪动都清空采集。只有**手不够**才重置。
- **漂移相对"开窗那一帧"测**，不是相对上一帧 —— 否则缓慢爬行的手能一帧帧积累到很远
  而不被发现。
- **保持完成到开始录动作之间给一拍**。上一版一保持完就开始，手从静止姿势移到动作起点
  那段路被当成动作的一部分，而用户根本没意识到指令变了。
- **"动作结束"是幅度不再变化**，不是手回到起点。大多数人做完动作会把手放回去，用"回到
  起点"当结束条件会和"拒绝往复动作"打架，两者交集为空。

**静态还是动态是用户选的**，不按动作名查表。硬编码那版既拒绝了"用画圈打开某个功能"
（适合动态的动作被强制静态），也在静止姿势就够用的地方强加了做动作的步骤。有律的动作
（挥动/倾斜）例外：方向由律决定，录制只是加一道"必须是这个手型"的门。

## 预览是精华

录完之后怎么知道录对了？只显示"已录制"的话，用户唯一的验证手段是摆一遍看有没有反应 ——
而那把「录错了」和「匹配没过」混成同一个症状。所以每条录制都画出来：

- **静态**：一格骨架图
- **动态**：起始姿势 + 一格动图（在关键帧之间插值，走完停一下换个颜色再重放）
- **倾斜类**：起始姿势 + 倾斜到触发角的样子 —— 而不是让用户看一个角度数字自己想象

几何在 `preview.js`（纯函数，19 项用例），绘制在 dashboard。几个搬过来时保留的非显然决定：

- **插值而不是切帧**：关键帧是连续动作的抽稀采样，直接切会看成卡顿，而真实手势没有那个
  卡顿 —— 那是预览在说谎
- **按包围盒 fit 而不是各手独立归一化**：双手模板共用一个原点和尺度，"两手的间距"本身
  就是签名的一部分，独立归一化会把它抹掉
- **先加 class 再量尺寸**：class 决定 `clientWidth`，反过来的话第一次绘制会把双手姿势
  塞进单手的框里
- **空预览是虚线框，不是塌掉的元素**："还没录"要看得出来是一个状态

## 普通 / 进阶不是"手势分两档"

是**有没有手势**：

| | |
|---|---|
| 普通 | 鼠标交互，不开摄像头 |
| 进阶 | 手势控制，全部动作开放，全部可自己录制 |

**默认是进阶** —— 这个产品的卖点就是手势，藏在开关后面等于默认交付一个只能用鼠标的
壁纸。普通模式留给"只想要个好看壁纸"的人。

每个可录制动作都有同样的选项（静态/动态 · 单手/双手），**包括有内置律的那些**。
`law` 只说明默认怎么触发，不锁死怎么录：选了动态就走关键帧序列，那时律让位。

## 手骨架和指针

**独立窗口**（`overlay.html`），盖在所有窗口之上、鼠标穿透。默认开，开关在「手势录制」栏。

第一版画在壁纸上，那是结构性错误：壁纸在最底层，而**录制时 dashboard 在最前面** ——
骨架会在最需要它的那一刻被挡住。而且它的用途不只是装饰壁纸，是"手在哪、有没有被看到"
的唯一答案，那个问题在任何窗口在前时都成立。

三个设置缺一不可，而且缺了都不报错：

| 缺什么 | 后果 |
|---|---|
| `alwaysOnTop('screen-saver')` | 被别的窗口挡住 |
| `setIgnoreMouseEvents(true, {forward:true})` | **整个屏幕点不动** |
| `setVisibleOnAllWorkspaces` | 切 Space 后消失 |

没有它的时候，「手势没反应」和「手根本没被检测到」是**同一个症状**，而录制时的反馈只剩
文字提示 —— 用户不知道自己的手在画面里的哪个位置、有没有被看到。

- 两只手不同色调（"哪只手在动"一眼看出来）
- **录制时整体转暖色** —— 状态变化要有一个不用读文字就能察觉的信号
- 食指指尖画一个呼吸的指针环（"我在指哪"之前完全没有答案）
- 手丢了**保留最后一帧渐变淡出**，不瞬间消失：丢一两帧跟踪很常见，瞬间消失会让骨架
  频闪，那比没有骨架更让人以为出问题了
- 录制时还有一条**提示条**（在骨架窗口上，不在 dashboard）：骨架回答"手在哪"，提示条
  回答"现在该做什么" —— 录制时 dashboard 可能不在视线里，而"保持不动"这类指令错过了
  就录不成

## 录制时其他手势不生效

两道门，不是冗余：

- **sensor 侧**：录制时不调 `input.update`，防的是"判定被跑了"
- **主进程侧**：`ipcMain.on('gesture')` 第一行 `if (recordingAction) return`，防的是
  "事件从任何路径漏出来"

录制时做动作会经过各种中间姿势，触发已绑的动作 —— 而那些动作会切模块、转视角、甚至
退出模式，把录制打断。AirCursor 真机上就是这么坏的。

⚠️ 解除录制态的三条路（成功 / 失败 / 取消）都得记得，漏一条的症状是**手势永久失效**，
而那个症状指向的地方离真正的原因很远。有用例守着。
