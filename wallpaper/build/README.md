# 应用图标

`icon.icns` / `icon.iconset/` 是**生成出来的**，不是手画的。要改就改脚本重跑，
别直接修 png —— 否则下次谁重跑一遍你的修改就没了。

```
python3 _icon-build.py     # → icon-source-1024.png
```

三个脚本的分工：

| 文件 | 干什么 |
|---|---|
| `_icon-gen.py` | squircle 遮罩（macOS 的圆角是超椭圆 n≈5，不是圆角矩形）、渐变底、四周 8.5% 留白 |
| `_icon-curtain.py` | 极光帷幕渲染 —— **上缘锐利、下缘指数羽化**、竖向射线纹理 |
| `_icon-build.py` | 最终构图：上青（高而亮）+ 下蓝（低而沉）两条帷幕 |

## ⚠️ 为什么帷幕不是"一条弯曲的发光带"

做废了三轮才想明白：极光是**帷幕**，上缘锐而亮、往下垂落散开，**上下不对称**。
画成粗细均匀的曲线就变成丝带／DNA 螺旋／均衡器，一眼假。`curtain()` 里
`up=0.020`（上缘溢光很小）对 `height=0.38`（下缘垂落很长）就是这个不对称。

竖向射线（`ray=`）是极光和"发光色带"的另一个区别，而它**只作用在帷幕身体上、
不碰上缘亮芯** —— 否则上缘会被啃出缺口。

## ⚠️ icns 是手写二进制的

生成它的机器（Linux）没有 `iconutil`，所以 `_icon-build.py` 之后是按 icns 容器
格式直接拼字节（magic + 类型码 + PNG 载荷）。结构自校验过（11 档都能解回合法
PNG），**但"Finder / Dock 认不认"在那台机器上验不了**。

⟹ `build-mac.sh` 在真机打包时会用 Apple 的 `iconutil` 从 `icon.iconset/`
**重生成一遍**，得到权威产物。仓库里那个手写的 icns 只是兜底。
